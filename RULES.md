# Theseus Cloud Shell — portable operational rules

**Source:** `TeaShaman-cyber/theseus-cloud-shell`. **Precedence:** installed Project Contract > selected named project router skill > this RULES.md > selected provider adapter > vendor docs.

1. Route work to the thinnest available governed shell. Prefer **exe.dev** when its *live* MCP/VM capability fits. Fly Sprites then MarcoPolo are justified fallbacks, not mandatory hops.
2. Identify the VM from current `list_vms`; a remembered name, URL, or cached capability is not proof of the correct target.
2a. When the provider-native `exe` integration is attached to the selected VM, exe.dev account-control commands are available through the guest HTTPS bridge `https://exe.int.exe.xyz/exec`; this is a verified executable control route even though it is not a direct ChatGPT MCP action. Re-probe attachment/current target, verify with a safe read-only POST, and preserve permission boundaries. Missing direct MCP `integrations`/billing/lifecycle actions or failed nested `ssh exe.dev` does not prove the bridge unavailable. See `providers/exe-dev/README.md`.
3. Differentiate MCP control-plane failure, guest process/exit, GitHub/API response and authoritative target readback. After an ambiguous stateful failure, inspect before retrying. Bound stdout and command size.
3a. Guest shell composition is part of the route contract: avoid `bash -lc` unless login semantics are required because it can replace PATH and hide governed helpers under `~/.local/bin`. Prefer documented absolute wrapper paths or explicitly verify the inner-shell PATH before declaring a helper absent.
4. Native `git`/`gh` OAuth, provider-integrated GitHub, administrator SSH/API, the guest OS keyring and rotating OAuth refresh tokens are **separate** surfaces. Do not expose secrets in model output, Git, command args, or logs.
5. `get_cli_help` is documentation, not execution. Never claim exe.dev `pause/resume`, billing or integration administration is reachable via MCP without live evidence. Direct guest SSH cannot stand in for provider-admin SSH.
6. Run the smallest existing deterministic repo QA before bespoke checks. Make narrow, reversible changes and independently read back important writes.
7. A new cloud provider belongs under `providers/` in **this repository**, rather than a new project-owned repository. Portable mechanics live under `modules/`; source provenance and runtime constraints stay explicit.
8. Large experiment artifacts require an owner, source/acceptance identity, retention trigger and cleanup postcondition at creation; later classify and verify candidates rather than deleting by size/name. Use [artifact housekeeping](docs/artifact-housekeeping.md), modeled on the Neon #235 inventory.\n9. Maps generated by CI are non-authoritative navigation artifacts. Git at exact SHA owns source; runtime settings/secrets and service health require their own independent probes.
